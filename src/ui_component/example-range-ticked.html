RangeTicked

A range input with native tick marks and a visible row of numeric labels underneath

1. Basic (1-25)

25 stops, under the default 30-stop threshold — ticks and a thinned set of visible numbers render automatically.

Drag the slider to see the value here

2. Including 0 as a "none" stop

Nothing special about 0 to this component — it's just another stop. Whether 0 means "nothing selected" is a decision the host page makes when it reads the value.

Drag the slider to see the value here

3. A wide range skips ticks entirely

46 stops (20 to 200 by 4) is at or above the default tick-threshold of 30, so this renders as a plain range input — no ticks, no datalist, no label row.

4. Tuning the thresholds

tick-threshold lowered to 15 turns ticks off for this 0-20 range (21 stops, otherwise under the default threshold of 30). max-visible-labels raised to 20 shows a denser set of numbers on a 0-28 range (29 stops) than the default cap of 13 would.

tick-threshold="15" (21 stops, ticks off)

max-visible-labels="20" (29 stops, ticks on)

5. Programmatic Access

Get and set the value from JavaScript. Setting .value moves the slider without firing range-changed.

API Reference

Attributes

min (number, default: 0)
max (number, default: 100)
step (number, default: 1)
A zero or negative value falls back to 1.
value (number, default: min)
Safe to set after connection — updates the live slider directly, does not rebuild the component.
tick-threshold (number, default: 30)
Stop count ceiling for showing ticks/labels at all.
max-visible-labels (number, default: 13)
Cap on visible number text once ticks are showing; the datalist still ticks every stop.

Properties

Every attribute above has a matching camelCase JS property: min, max, step, value, tickThreshold, maxVisibleLabels.

Methods

getValue()
Returns the current value as a number. Symmetric with the .value property.

Events

range-changed
Fired on every drag tick. Detail:
{ value: number }
